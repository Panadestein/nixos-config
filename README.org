Welcome to my [[https://nixos.org/][NixOS]] system flake, using [[https://nix-community.github.io/home-manager/][Home Manager]] 
for the user environment. After many turbulent iterations and headaches, this is the deepest local minimum I have found; a world
reborn.

The machine is named [[https://en.wikipedia.org/wiki/Cyrus_Smith][cyrus]], after Verne's engineer and one of my childhood heroes.
Its Wayland desktop runs [[https://hypr.land/][Hyprland]] exclusively. The config emphasises coherence, robustness, and
minimalism: no bullshit features for its own sake.

Visually, the system draws its character from the landscapes of [[https://en.wikipedia.org/wiki/Ernst_Ferdinand_Oehme][Ernst Ferdinand Oehme]],
an unsung painter of the German Romantic period. The tracked wallpaper collection, together with notes on the works, lives

** Build and apply changes

Run commands from the repository root. I prefer [[https://github.com/nix-community/nh][nh]] for NixOS builds and
deployments: it knows this flake's configured location, selects the local host,
and provides useful build output and package diffs. First validate the flake and
build the system and Home Manager configuration without activating it:

#+begin_src bash
  nix flake check --no-write-lock-file
  nh os build
#+end_src

A build checks generated files and package dependencies; it cannot exercise docking
or suspend on hardware. New files must be added with =git add= before a Git-backed flake
can see them.

Apply the configuration:

#+begin_src bash
  nh os switch
#+end_src

Log out and back in after changes to the session environment or compositor.
=Super+Ctrl+R= reloads the /installed/ Hyprland configuration; repository edits
take effect after rebuilding.

*** Update dependencies

Update one input at a time, then repeat the checks above:

#+begin_src bash
  nix flake update <INPUT>
#+end_src

or all of them together:

#+begin_src bash
  nix flake update
#+end_src

=nh= can also update inputs as part of a build or deployment (=nh os build
--update=, =nh os switch --update=, or =--update-input <INPUT>=), but it does
not provide a lockfile-only update command. Use =nix flake update= when the
intent is to update and review =flake.lock= before building.

Keep the existing =stateVersion= values when upgrading: they describe compatibility
defaults, not the desired NixOS release.

** Development environment

The principal flake provides small, current nixpkgs-based development environments:

| Command                          | Environment                                      |
|----------------------------------+--------------------------------------------------|
| =nix develop=                    | Nix formatting and static analysis               |
| =nix develop .#python=           | Scientific Python and Jupyter                    |
| =nix develop .#c-cpp=            | C/C++ compilers, build tools and debugging       |
| =nix develop .#fortran-mpi=      | Fortran, Open MPI, fortls and fypp               |
| =nix develop .#julia=            | Julia                                            |

Home Manager enables direnv and nix-direnv for Bash, Fish and Zsh. The repository's
=.envrc= selects the default maintenance shell; approve it once with =direnv allow=.

*** Formatting, linting and pre-commit hooks

The default development shell installs the repository's pre-commit hook. It runs
=nixfmt= to format Nix, =statix= for style and correctness checks, and =deadnix= to
find unused Nix code. Enter it with =nix develop= (or let direnv load it), then run
all hooks manually before committing when useful:

#+begin_src bash
  prek run --all-files
#+end_src

=nix flake check --no-write-lock-file= also runs this hook suite as the
=pre-commit= flake check, making it suitable for CI or a clean, reproducible
validation pass.
